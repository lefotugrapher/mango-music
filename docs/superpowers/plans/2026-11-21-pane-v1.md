# Pane v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static web player with an Apple-Music-style Liquid Glass interface that plays the user's own Spotify account through a Client ID they supply.

**Architecture:** A Vite + React single-page app with no backend. Screens talk to two contracts, `MusicSource` (browse data) and `PlayerEngine` (transport), each with a demo implementation and a Spotify implementation. Phase A builds the whole interface on the demo implementations; Phase B adds PKCE login, the Web API client, and the Web Playback SDK behind the same contracts.

**Tech Stack:** Vite 8, React 19, TypeScript 7, react-router 8 (hash router), zustand 5, @tanstack/react-query 5, motion 14, @phosphor-icons/react 2, Vitest 5 + Testing Library + jsdom. Plain CSS with custom properties.

**Spec:** `docs/superpowers/specs/2026-11-21-pane-design.md` — read it before any task.

## Global Constraints

- No Apple name, logo, SF Symbols, or SF font files anywhere in the repo. No name or logo resembling Spotify's.
- No Client ID, client secret, or token committed. No server code. No unofficial Spotify endpoints.
- Glass (`Glass` component) only on navigation and controls, never on content cards. At most 4 refracting surfaces on screen. Never change filter parameters per frame; animate glass with `transform` and `opacity` only.
- Album and playlist covers: square, small corner radius, never circular, never text on top. Only artist images may be circular.
- Honour `prefers-reduced-motion` and `prefers-reduced-transparency`.
- Vite `base: './'`; hash routing; the OAuth redirect lands on the app root. Dev server binds `127.0.0.1:5173` with `strictPort`.
- Redirect URI is derived from the current origin. `localhost` is never offered as a redirect URI.
- Auth is Authorization Code with PKCE. Scopes, exactly: `streaming user-read-private user-read-playback-state user-modify-playback-state user-read-currently-playing user-library-read user-library-modify user-top-read user-read-recently-played playlist-read-private playlist-read-collaborative user-follow-read`.
- Web Playback SDK script: `https://sdk.scdn.co/spotify-player.js`. Device name: `Pane`.
- Storage keys: `pane.clientId`, `pane.tokens`, `pane.settings`, `pane.cache.newFromArtists` (localStorage); `pane.pkce` (sessionStorage).
- Font stack: `-apple-system, BlinkMacSystemFont, "Inter", "Segoe UI", system-ui, sans-serif`. Icons: Phosphor only.
- Demo content is invented: no real artist, album, or track names; artwork is generated gradients.
- Dependencies: exact versions (`--save-exact`), installed with `--ignore-scripts`, each direct dependency checked with `npm view <pkg>@<version> scripts maintainers repository` first; prefer a version published at least 7 days ago. Run `npm audit signatures` after install.
- These library versions are newer than the planner's training data. Check the installed package's own docs or types before using an API from memory.
- Commits: plain messages, no `Co-Authored-By` or "Generated with" lines. Work on branch `v1`. Never push; pushing needs Kayzee's explicit yes.
- Tests live beside source as `*.test.ts(x)`. `npm test` runs `vitest run`; `npm run typecheck` runs `tsc --noEmit`.

## Review Focus

1. **App opened at `http://localhost:5173`.** Spotify rejects that redirect URI. Setup must detect it, explain, and link to the `127.0.0.1` address. → Task 9.
2. **Token lifecycle across tabs and time.** Two open tabs refreshing at once, or a refresh token Spotify has revoked, must not strand the user on a blank screen: tabs share one refresh, and a dead refresh token returns to Setup with a message. → Tasks 10, 14.
3. **Dirty playlist and library items.** Spotify returns `null` tracks, local files with no id, podcast episodes, and unplayable tracks. They are skipped or shown disabled; nothing crashes. → Task 12.
4. **Empty or brand-new account.** No history, no saved items, a failing shelf request. Home and Library show empty states, not a blank page or an error. → Tasks 7, 12.
5. **Free account or a browser without DRM.** The SDK reports `account_error` or `initialization_error`. Browsing still works and the reason is stated. → Tasks 13, 14.

### Task 2: Glass system

**Files:** Create `src/glass/tier.ts`, `displacement.ts`, `GlassFilterHost.tsx`, `Glass.tsx`, `glass.css`, `src/screens/GlassLab.tsx`. Tests: `tier.test.ts`, `displacement.test.ts`, `Glass.test.tsx`.

**Interfaces — Produces:**
- `type GlassTier = 'refract' | 'blur' | 'solid'`
- `detectGlassTier(env: { isChromium: boolean; supportsBackdrop: boolean; supportsBackdropUrl: boolean; reducedTransparency: boolean; setting: 'auto' | 'blur' | 'solid' }): GlassTier`
- `readGlassEnv(setting): env` (reads `navigator.userAgentData`, `CSS.supports`, `matchMedia`)
- `buildDisplacementMap(o: { width: number; height: number; radius: number; bezel: number }): string | null` — an SVG data URL
- `<GlassFilterHost tier>` — mounts one hidden `<svg>` and provides a context that registers a filter per (width, height, radius) and returns its id
- `<Glass as? material?: 'regular' | 'clear' radius?: number tint?: string className? style?>` — sets `data-tier` and `data-material`

Approach: the map is mid-grey (no shift) with a band `bezel` px wide along the rounded edge where the red channel ramps for x and green for y, pushing samples inward like a convex lens. The filter is `feImage` (the map) → `feDisplacementMap` (`in="SourceGraphic"`, `xChannelSelector="R"`, `yChannelSelector="G"`) → a slight `feGaussianBlur`; CSS applies `backdrop-filter: url(#id) saturate() brightness()`. Tier `blur` uses `backdrop-filter: blur() saturate()` (plus the `-webkit-` form). Tier `solid` uses `--bg-elevated` with no filter. Every tier draws the specular rim (inset gradient border) and a soft shadow. `Glass` measures itself with `ResizeObserver` and re-registers only when its rounded size changes. `GlassLab` is a dev-only route (`#/__glass`) showing each material over photos, text, and both themes, for tuning by eye.

**Interfaces — Produces:**

- `createSpotifySession(clientId: string): Promise<Session & { tokens: TokenStore }>`

Boot: a `code` or `error` in the query → `completeLogin`, then strip the query with `history.replaceState`; stored Client ID and tokens → restore; otherwise Setup. Connect stores the Client ID and calls `beginLogin`. Disconnect clears tokens, disposes the player, and clears the query cache, keeping the Client ID. Change Client ID clears both. If the SDK fails to load, the session still starts with browsing, and the player reports `unsupported_browser`.

Notices shown on Setup: denied → "Spotify sign-in was cancelled."; state mismatch or exchange failure → "Sign-in didn't complete. Try again."; signed out → "Spotify signed you out. Connect again." An API `forbidden` error during restore → "This Spotify account isn't on the app's user list. Add it under User Management in the Spotify dashboard."
